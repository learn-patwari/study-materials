Elasticsearch — Distributed Search & Analytics
Core Concepts
Index
A collection of JSON documents. Equivalent to a database table. Named in lowercase.
Document
A single JSON record stored in an index. Has a unique _id, _index, and fields.
Shard
A horizontal partition of an index. Each shard is a full Lucene instance. Enables parallelism.
Replica
A copy of a primary shard. Provides fault tolerance and read scalability. Never on same node as primary.
Cluster / Node
Cluster = group of nodes. Node types: Master (metadata), Data (stores/queries), Coordinating (routes requests).
Mapping
Schema for an index. Defines field types: text (analyzed), keyword (exact), date, long, etc.
Inverted Index
Core data structure: maps every term to the documents containing it. Enables sub-second full-text search.
Aggregation
Analytics over documents: terms, date_histogram, avg, sum, cardinality. Runs alongside search.

Java Integration (Spring Boot)
Java — Spring Data Elasticsearch + Low-level client
// 1. Dependency — pom.xml
// spring-boot-starter-data-elasticsearch

// 2. Document entity
@Document(indexName = "transactions")
public class Transaction {
    @Id
    private String id;

    @Field(type = FieldType.Text)
    private String description;

    @Field(type = FieldType.Keyword)
    private String accountNumber;

    @Field(type = FieldType.Double)
    private Double amount;

    @Field(type = FieldType.Date)
    private LocalDateTime timestamp;
}

// 3. Repository
public interface TransactionRepository
    extends ElasticsearchRepository<Transaction, String> {

    List<Transaction> findByAccountNumber(String accountNumber);
}

// 4. Custom query with ElasticsearchOperations
@Service
public class TransactionSearchService {

    @Autowired
    private ElasticsearchOperations ops;

    public SearchHits<Transaction> searchFraud(String account, double minAmount) {
        Query query = NativeQuery.builder()
            .withQuery(QueryBuilders.bool()
                .must(QueryBuilders.term()
                    .field("accountNumber")
                    .value(account).build()._toQuery())
                .filter(QueryBuilders.range()
                    .field("amount")
                    .gte(JsonData.of(minAmount)).build()._toQuery())
                .build()._toQuery())
            .build();
        return ops.search(query, Transaction.class);
    }
}

SonarQube — Static Code Analysis & Quality Gates
Core Concepts
Quality Gate
Pass/fail threshold applied to a project (e.g. coverage > 80%, 0 new bugs). Build fails if gate fails.
Quality Profile
Ruleset per language. Default: Sonar way. Banking: often custom profile with OWASP + CERT Java rules.
Bug
Code that is likely to cause incorrect behavior at runtime. Highest severity — must fix before merge.
Vulnerability
Security weakness that could be exploited (SQL injection, XSS, insecure random). Maps to OWASP/CWE.
Code Smell
Maintainability issue — not a bug, but increases technical debt (e.g. too many params, duplicated blocks).
Security Hotspot
Code requiring human review — not necessarily a vulnerability, but sensitive (e.g. crypto algorithm choice).
Technical Debt
Estimated time to fix all code smells. SQALE method rates maintainability A–E. A = best.
Coverage
% of lines/branches covered by unit tests (JUnit). SonarQube reads Jacoco XML report.

pipeline {
    agent any
    environment {
        SONAR_TOKEN = credentials('sonar-token')
    }
    stages {
        stage('Build & Test') {
            steps {
                sh 'mvn clean verify'  // runs JUnit + Jacoco
            }
        }
        stage('SonarQube Analysis') {
            steps {
                withSonarQubeEnv('SonarQube') {
                    sh """
                        mvn sonar:sonar \
                          -Dsonar.projectKey=myapp \
                          -Dsonar.coverage.jacoco.xmlReportPaths=\
                            target/site/jacoco/jacoco.xml
                    """
                }
            }
        }
        stage('Quality Gate') {
            steps {
                timeout(time: 5, unit: 'MINUTES') {
                    waitForQualityGate abortPipeline: true
                }
            }
        }
    }
}

Banking & Regulatory Context

  • OWASP Top 10 enforcement — SonarQube rules map directly to OWASP categories. French banks enforce A1 (injection), A2 (broken auth), A3 (sensitive data exposure) as blocking issues.
  • PCI DSS compliance — vulnerabilities related to cardholder data handling (insecure random, hard-coded credentials, weak crypto) must score A on Security Rating before any deployment.
  • Security Hotspot review process — all hotspots require a named reviewer to mark "Acknowledged" or "Safe" with justification. Audit trail is preserved in SonarQube for regulatory inspection.
  • Branch and PR decoration — SonarQube comments on every PR with new issues introduced, preventing vulnerabilities from entering main.
  • SonarLint in IDE — developers catch issues locally before commit; same rules as server, zero surprise at pipeline stage.

Core Services (mapped to your existing skills)
EKS / ECS
Managed Kubernetes (EKS) and container service (ECS). Your Kubernetes skills transfer directly to EKS.
MSK
Managed Streaming for Apache Kafka. Your Kafka knowledge applies 1:1 — same producer/consumer API.
ElastiCache
Managed Redis/Memcached. Your Redis experience maps directly — same commands, managed infra.
IAM
Identity & Access Management — roles, policies, least privilege. Conceptually similar to Keycloak RBAC.
RDS
Managed relational DB (Oracle, MySQL, PostgreSQL). Multi-AZ for HA. Your Oracle/MySQL experience applies.
S3
Object storage. Store files, backups, ML model artefacts. Buckets, versioning, lifecycle policies, presigned URLs.
SQS / SNS
SQS = queue (point-to-point, like RabbitMQ). SNS = pub/sub fan-out. Both integrate with Spring Boot.
CloudWatch
Metrics, logs, alarms. Equivalent to Grafana + log aggregation. Java apps push via CloudWatch agent or SDK.
VPC
Isolated network. Subnets (public/private), Security Groups (stateful firewall), NACLs, Internet Gateway.
Lambda
Serverless functions. Event-driven — triggered by S3, SQS, API Gateway. Supports Java 21 runtime.
CloudTrail
Audit log of every AWS API call. Critical for banking compliance — who did what, when, from where.
KMS
Key Management Service. Encryption at rest for RDS, S3, EBS. Required for PCI/financial data.

Banking & Regulatory Context — Singapore / French Bank

  • Multi-AZ deployment — RDS and EKS nodes span at least 2 availability zones. MAS (Monetary Authority of Singapore) requires DR capability.
  • KMS encryption — all data at rest (RDS, S3, EBS) encrypted with customer-managed KMS keys. Key rotation enforced annually for PCI DSS.
  • IAM least-privilege — EKS pods use IAM service accounts (IRSA) with scoped policies. No shared credentials; no hardcoded access keys.
  • VPC isolation — banking workloads run in private subnets. No public IP for data services. Direct Connect or VPN to on-prem trading systems.
  • CloudTrail + CloudWatch Logs Insights — full audit trail of all API calls; log retention minimum 7 years for MAS compliance.
  • MSK for Kafka — avoids self-managing Kafka brokers; TLS + IAM auth; in-transit encryption mandatory for financial message streams.
